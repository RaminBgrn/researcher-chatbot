# Researcher Chatbot — چت‌بات پژوهشگر

یک چت‌بات پژوهشی ساده که با **Python (Flask)** و **HTML/CSS/JavaScript** ساخته شده است.

کاربر یک موضوع وارد می‌کند؛ چت‌بات درباره آن موضوع تحقیق می‌کند، یک گزارش ساخت‌یافته می‌نویسد و گزارش را به صورت فایل در سیستم ذخیره می‌کند.

## ویژگی‌ها

- تحقیق درباره هر موضوع با استفاده از ویکی‌پدیا یا جستجوی وب (Tavily) برای اطلاعات تازه
- تولید گزارش ساخت‌یافته شامل عنوان، خلاصه، نکات کلیدی و نتیجه‌گیری
- ذخیره خودکار هر گزارش در یک فایل Markdown داخل پوشه `outputs/`
- چند گفتگوی همزمان با هیستوری جدا، در سایدبار: ساخت، جابه‌جایی و حذف گفتگو
- سایدبار تب‌دار (گفتگوها / JSON / فاکتورها / تنظیمات): در تب JSON، رفت‌وبرگشت با مدل به صورت ردیفی «کلید و مقدار» نمایش داده می‌شود و JSON خام هم قابل کپی است
- ذخیره دستی گزارش: زیر هر جوابِ مبتنی بر فراخوانی ابزار، دکمه «ذخیره گزارش» می‌آید و فقط با کلیک کاربر گزارش در outputs ذخیره می‌شود (ذخیره خودکار وجود ندارد)
- تب فاکتورها: قبض توکنی هر دور گفتگو به صورت لیست، با ورودی/خروجی/جمع واقعی از usage API و شکست تخمینی ورودی (سیستم، ابزارها، هیستوری) و finish_reason
- تب تنظیمات توکن: سقف توکن خروجی (`max_tokens`)، بودجه توکنی هیستوری (با حذف بلوکی پیام‌های قدیمی) و حداکثر دور ابزار، به همراه آمار تخمینی توکن گفتگوی جاری
- تم روشن و تیره با حالت «سیستم»؛ انتخاب تم در مرورگر ذخیره می‌شود
- رابط کاربری مدرن، راست‌چین (فارسی) و کاملاً ریسپانسیو؛ در موبایل سایدبار به صورت کشویی باز می‌شود

## API

| Method | Path | توضیح |
|---|---|---|
| GET | `/api/chats` | فهرست گفتگوها |
| POST | `/api/chats` | ساخت گفتگوی تازه |
| GET | `/api/chats/<id>` | پیام‌های یک گفتگو |
| POST | `/api/chats/<id>/message` | ارسال پیام به یک گفتگو |
| DELETE | `/api/chats/<id>` | حذف یک گفتگو |
| POST | `/api/chat` | ارسال پیام به گفتگوی پیش‌فرض (سازگاری با نسخه قبل) |
| POST | `/api/clear` | پاک کردن هیستوری گفتگوی پیش‌فرض |

## چطور کار می‌کند

این پروژه سه مفهوم اصلی کار با مدل‌های زبانی را پیاده‌سازی می‌کند:

1. **System Prompt** — رفتار و قوانین چت‌بات در یک فایل جدا (`prompts.py`) تعریف شده و به عنوان اولین پیام برای مدل فرستاده می‌شود.
2. **Tool Calling** — مدل سه ابزار در اختیار دارد و خودش تصمیم می‌گیرد کی از آن‌ها استفاده کند:
   - `search_wikipedia` : جستجو و دریافت خلاصه یک موضوع از ویکی‌پدیا
   - `search_web` : جستجو در کل وب با Tavily، برای اطلاعات تازه (نیازمند `TAVILY_API_KEY` در `.env`)
   - `get_weather` : آب‌وهوای فعلی یک شهر از OpenWeather (نیازمند `OPEN_WEATHER_KEY` در `.env`)

   ذخیره گزارش ابزار مدل نیست: وقتی در یک نوبت تحقیقی انجام شده باشد، خود برنامه بعد از آماده شدن جواب نهایی، گزارش را به صورت خودکار در فایل ذخیره می‌کند و اسم فایل را به پاسخ اضافه می‌کند.
3. **History Management** — مدل حافظه داخلی ندارد؛ کل تاریخچه گفتگو (پیام سیستم، کاربر، فراخوانی ابزارها و پاسخ‌ها) در هر درخواست دوباره برای مدل فرستاده می‌شود.

جریان یک درخواست:

```
کاربر موضوع را می‌فرستد
   → مدل ابزار تحقیق (مثلاً search_wikipedia) را فراخوانی می‌کند
   → نتیجه تحقیق به مدل برگردانده می‌شود
   → مدل گزارش را در جواب نهایی می‌نویسد
   → برنامه گزارش را خودکار در فایل ذخیره می‌کند و پاسخ به کاربر نمایش داده می‌شود
```

## ساختار پروژه

| فایل | نقش |
|---|---|
| `app.py` | سرور Flask؛ صفحه چت و API های آن |
| `chatbot.py` | مدیریت تاریخچه گفتگو و حلقه اجرای tool call ها |
| `prompts.py` | سیستم پرامپت چت‌بات |
| `tools.py` | تعریف و پیاده‌سازی ابزارها |
| `templates/index.html` | صفحه چت |
| `static/style.css` | استایل صفحه |
| `static/app.js` | منطق سمت کاربر (ارسال پیام و نمایش پاسخ) |
| `outputs/` | محل ذخیره گزارش‌های تولیدشده |

## نصب و اجرا

پیش‌نیاز: Python 3.10 به بالا و یک API key از یک سرویس سازگار با OpenAI.

```bash
pip install -r requirements.txt
```

یک فایل `.env` بر اساس `.env.example` بسازید و مقادیر آن را کامل کنید:

```env
API_KEY=your_api_key
BASE_URL=https://your-provider.example/v1/
MODEL_NAME=your_model_name
```

سپس سرور را اجرا کنید:

```bash
python app.py
```

و در مرورگر باز کنید: http://localhost:5000

> فایل `.env` حاوی کلید خصوصی است؛ آن را در گیت کامیت نکنید (در `.gitignore` قرار داده شده است).
