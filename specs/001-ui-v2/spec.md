# Feature Specification: بهبود رابط کاربری (UI v2)

**Feature Branch**: `001-ui-v2`
**Created**: 2026-10-30
**Status**: Approved for implementation (درخواست مستقیم کاربر)

## User Scenarios

### User Story 1 — سایدبار گفتگوها (Priority: P1)
کاربر می‌خواهد همه گفتگوهایش را در یک سایدبار ببیند، بین آن‌ها جابه‌جا شود و گفتگوی تازه بسازد؛ مثل تجربه چت‌بات‌های امروزی.

**Acceptance**:
- سایدبار فهرست گفتگوها را با عنوان هر گفتگو (اولین پیام کاربر) نشان می‌دهد.
- کلیک روی هر گفتگو، پیام‌های همان گفتگو را بارگذاری می‌کند.
- دکمه «چت جدید» یک گفتگوی خالی تازه می‌سازد و فعالش می‌کند.
- هر گفتگو قابل حذف است؛ گفتگوی فعال در فهرست مشخص است.

### User Story 2 — تم روشن/تیره (Priority: P1)
کاربر می‌خواهد بین حالت تیره و روشن انتخاب کند و انتخابش بماند.

**Acceptance**:
- سوییچ تم در هدر همیشه در دسترس است: روشن / تیره / سیستم.
- حالت «سیستم» از تنظیم سیستم‌عامل پیروی می‌کند.
- انتخاب کاربر در مرورگر ذخیره و در بازدید بعدی اعمال می‌شود.
- هر دو تم کنتراست خوانا دارند.

### User Story 3 — ریسپانسیو (Priority: P1)
کاربر روی موبایل هم تجربه کامل می‌خواهد.

**Acceptance**:
- در عرض کمتر از ۸۶۰px سایدبار به صورت کشویی (Drawer) با دکمه همبرگری باز و بسته می‌شود و پس‌زمینه تیره (Overlay) دارد.
- در دسکتاپ سایدبار ثابت کنار محتوای چت است.
- ناحیه پیام و ورودی در همه عرض‌ها کامل و قابل استفاده‌اند.

### Edge Cases
- حذف گفتگوی فعال: یک گفتگوی تازه ساخته و فعال می‌شود.
- گفتگوی بدون پیام: با عنوان «گفتگوی جدید» در فهرست دیده می‌شود.
- نبود API key: رفتار فعلی (پیام خطای واضح داخل همان گفتگو) حفظ می‌شود.

## Requirements

- **FR-001**: سیستم باید چند گفتگوی همزمان (در حافظه سرور) نگه دارد و برای هر کدام هیستوری جدا داشته باشد.
- **FR-002**: API گفتگوها: فهرست، ساخت، خواندن پیام‌ها، ارسال پیام به گفتگوی مشخص، حذف.
- **FR-003**: API های قبلی (`/api/chat` و `/api/clear`) برای سازگاری باقی می‌مانند و روی گفتگوی پیش‌فرض کار می‌کنند.
- **FR-004**: عنوان هر گفتگو از اولین پیام کاربر ساخته می‌شود (کوتاه‌شده).
- **FR-005**: تم با متغیرهای CSS و ویژگی `data-theme` پیاده می‌شود؛ بدون فریم‌ورک فرانت‌اند تازه.
- **FR-006**: چیدمان با Grid/Flexbox و mobile-first است؛ بریک‌پوینت اصلی 860px.
- **FR-007**: اصول طراحی Agency (پاس UI Designer و UX Architect): توکن‌های طراحی و رنگ‌های معنایی، مقیاس فاصله ۴/۸، حالت‌های فوکوس قابل مشاهده، اهداف لمسی حداقل 44px، و سوییچ تم سه‌حالته سیستم/روشن/تیره با ذخیره‌سازی امن (try/catch).

## Success Criteria

- **SC-001**: ساخت، فهرست، ارسال پیام، جابه‌جایی و حذف گفتگو در تست API همه موفق‌اند.
- **SC-002**: صفحه اصلی با هر سه فایل فرانت بدون خطا بارگذاری می‌شود.
- **SC-003**: هیچ وابستگی تازه‌ای به پروژه اضافه نشده است.
- **SC-004**: سه مفهوم اصلی پروژه (پرامپت/ابزار/هیستوری) دست‌نخورده باقی مانده‌اند؛ تغییر بک‌اند فقط مدیریت چند گفتگوست.
